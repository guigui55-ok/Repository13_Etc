**20～30行程度の詳細ルールを全部ここへ入れる使い方は、必須ではありません。**
この欄は小さく見えますが長文入力自体はできます。ただ、実際の運用としては、私は次のように分ける方が自然だと思います。

### Project instructions

「このProject全体で常に守ってほしい基本方針」だけを書く。

例えば：

```text
このプロジェクトでは、ソフトウェア開発に関する調査、設計、実装、テスト、運用の検討と、関連ドキュメントの作成・レビューを行います。

回答では最初に結論を示し、複数案がある場合は推奨案を明確にしてください。

要件・設計・実装・テスト・運用の整合性を重視してください。不明点を推測で確定せず、確定事項と未確定事項を区別してください。

理論上の理想だけでなく、実際の作業効率、保守性、再利用性を重視してください。
```

このくらい、**10行前後でも十分**だと思います。

一方で、

```text
影響調査の具体的な9観点
ドキュメント同期の手順
レビュー時のチェックリスト
Agent設定の評価基準
```

などは、Project instructions に全部入れず、

```text
impact-analysis.md
doc-sync.md
consistency-review.md
```

のような別ファイルや、その作業用のチャット内プロンプトに分ける方がよいです。

公式にもProjectsは、**チャット、参考ファイル、カスタム指示を組み合わせて使うワークスペース**として説明されているため、すべてを1つのInstructions欄に詰め込む必要はありません。 ([OpenAI Help Center][2])

私の考えとしては、前に提案した20～30行版は少し「全部入り」に寄りすぎていました。
今回のToshiさんの構成では、**Project instructionsは短めの共通方針だけにする**方がよいと思います。
