# プロジェクトの目的

本プロジェクトでは、ソフトウェア開発に関するドキュメントの作成、レビュー、変更反映、整合性確認を行う。

# 基本方針

* 要件、設計、仕様、テスト、運用の整合性を重視する。
* 変更内容を単純な文字列置換として扱わず、各記述の文脈を確認する。
* 変更履歴、調査経緯、不採用理由として残すべき情報を誤って削除しない。
* ユーザーが指定していない仕様を推測で追加しない。
* 不明点があっても、確定している範囲の分析や作業は進める。
* 既存ドキュメントの文体、章構成、用語、項番体系を尊重する。
* 修正後は、変更前情報の残存、項番、ID、参照関係、ドキュメント間の整合性を確認する。
