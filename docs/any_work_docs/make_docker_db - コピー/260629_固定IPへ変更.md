
実は、**今のタイミングがネットワーク構成を見直すベストタイミング**です。DockerやSQL Serverまで構築してから変更すると影響範囲が大きくなるため、今なら修正コストが低く済みます。

## なぜDefault Switchをやめるのか

今回の結果を見ると、

* VM2：`172.22.32.1`
* VM3：`172.17.133.21`

と**異なるネットワーク**になっています。

Default SwitchはHyper-Vが内部的にNATやDHCPを管理しており、VMごとに異なるセグメントになったり、IPが変わったりすることがあります。

学習用途としては便利ですが、

* VM間通信
* SQL Server接続
* Dockerコンテナ間通信
* 将来のProxy・DNSサーバー構築

には向いていません。

# 私がおすすめする構成

## External Switch

```text
                    自宅ルータ
                        │
                192.168.1.0/24
                        │
                External Switch
                        │
      ┌─────────┼──────────┐
      │         │          │
 WindowsVM   UbuntuDB   ProxyVM
 192.168.1.x 192.168.1.x 192.168.1.x
```

### メリット

* VM同士通信できる
* ホストPCから通信できる
* インターネット接続できる
* MobaXtermでSSHできる
* 実務でもよくある構成

## 実務ではもう一歩進めます

私なら、**この学習環境専用のネットワーク設計**として次のようにします。

* Hyper-V：External Switch
* DHCP：自宅ルータ
* 初期構築：DHCP
* 学習が進んだら、Ubuntuサーバーを**固定IP**へ変更

例えば、

| VM           | IP            |
| ------------ | ------------- |
| Windows開発VM  | 192.168.1.101 |
| Ubuntu DB    | 192.168.1.102 |
| Ubuntu Web   | 192.168.1.103 |
| Ubuntu Proxy | 192.168.1.104 |

このようにすると、SSHやSQL Serverの接続先が変わらず、実務でよく行われる「サーバーは固定IPで運用する」という考え方も自然に学べます。

私としては、**External Switch + DHCPで構築し、後で固定IP化する**のが、学習と実務のバランスが最も良い構成だと思います。
