## ⑤ データ（目的が達成できるか）

* 書き込み
* 整合性
* 更新

## ⑥ 障害（失敗したら）

## ⑦ 運用（続けられるか）

---

これを設計・実装・テストへ変換するとこうなります。

| 観点   | 設計   | 実装     | テスト  |
| ---- | ---- | ------ | ---- |
| 利用者  | 権限   | 認証処理   | 権限確認 |
| 接続条件 | 構成   | 設定     | 疎通   |
| 通信   | 方式   | タイムアウト | 性能   |
| 認証   | 方式   | 認証処理   | 認証試験 |
| データ  | モデル  | SQL    | 結果確認 |
| 障害   | 例外方針 | エラー処理  | 異常系  |
| 運用   | 手順   | ログ     | 運用確認 |

今回の理解を少しだけ言い換えるなら、

> **「接続できるか」だけではなく、「誰が・何の目的で・失敗時どうするか」まで考える**

です。

この考え方、サーバー・DB・API・画面・ファイル出力にもそのまま使えます。
