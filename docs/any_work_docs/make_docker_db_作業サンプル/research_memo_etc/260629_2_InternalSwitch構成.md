# Internalを使用する理由

## ① サーバー間通信をLANから分離する

実務では、

* DB通信
* Web⇔DB通信
* Proxy⇔Web通信

などは**外部LANを通さず、内部ネットワークだけで通信**します。

これにより、

* セキュリティ向上
* 不要な通信を減らす
* パフォーマンス向上

につながります。

---

## ② 外部へ公開する通信を限定する

例えばDBサーバーは、

```text
Internet
     │
 Web Server
     │
 DB Server
```

となり、

**DBはInternetから直接アクセスできません。**

これがInternalを使う一番の理由です。

---

## ③ 将来サーバーが増えても構成変更が少ない

今後予定している

* Docker
* SQL Server
* Proxy
* DNS
* Web

を追加しても、

Internal Switchへ接続するだけです。

ネットワーク設計を最初から変更する必要がありません。

---

## ④ 実務構成を再現できる

企業では、

```text
External
     │
Firewall
     │
Proxy
     │
Internal
     │
Web
     │
DB
```

のように

**内部ネットワークを持つ構成**が一般的です。

学習でもこれを再現できます。

### ネットワーク構成方針

```
Hyper-V上にExternal SwitchおよびInternal Switchを構成する。

External Switchはインターネット接続およびホストPCからの管理（SSH等）に使用する。

Internal SwitchはVM間の内部通信専用ネットワークとして使用し、
DB通信や各サーバー間通信を外部ネットワークから分離する。

これにより、
・サーバー間通信のセキュリティ向上
・役割ごとのネットワーク分離
・将来的なWebサーバー、Proxyサーバー等の追加に対応しやすい構成
を実現する。
```

# 私ならさらに一歩進めます

あなたの学習テーマは「**実務を学ぶこと**」ですよね。

そうであれば、**Internal Switchにはインターネットを流さない**ことを意識すると、より実務的になります。

例えば将来は、

* **NIC1（External）**：SSH・OS更新・Dockerイメージ取得など管理・外部通信用
* **NIC2（Internal）**：SQL Server、Web、Proxyなどサーバー間通信専用

という役割分担にすると、「どの通信をどのネットワークに流すべきか」というネットワーク設計の考え方まで学べます。これは実際の企業のインフラ設計でもよく採用される考え方です。
