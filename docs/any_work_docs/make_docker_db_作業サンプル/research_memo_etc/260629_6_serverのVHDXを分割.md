# 案1：パーティションを分ける

```
Disk1 (100GB)

C: (/)
    Ubuntu

D: (/data)
    Docker
    SQL Server
```

### メリット

* OS領域とデータ領域を論理的に分けられる
* OS再インストール時にデータを残せる可能性がある
* バックアップ対象を分けやすい

### デメリット

* **物理的には同じディスク**
* ディスク故障時は両方失われる
* 容量変更が少し面倒

# 案2：別VHDX（おすすめ）

例えば

```
Ubuntu_OS.vhdx
Ubuntu_Data.vhdx
```

Ubuntuでは

```
/
```

はOSディスク

```
/srv/docker
```

はデータディスク

としてマウントします。

### メリット

* データだけ別サーバーへ持っていける
* バックアップが容易
* データディスクだけ容量拡張できる
* 実務でもよくある構成

---

# 実務では？

企業ではこのような構成が一般的です。

```
Disk1
/
OS

Disk2
/var

Disk3
/data

Disk4
backup
```

または

```
OS
Data
Log
Backup
```

のように用途ごとに分けます。

SQL Serverなら

* データ
* トランザクションログ
* バックアップ

を別ディスクにすることも珍しくありません。

# Dockerなら

私は

```
Ubuntu_OS.vhdx
```

↓

```
/

Ubuntu_Data.vhdx
```

↓

```
/srv/docker
```

にします。

Docker Composeでは

```
/srv/docker/sqlserver/data
```

をマウントします。

すると

```
Ubuntu
↓
Docker
↓
SQL Server
```

ではなく

```
Ubuntu
↓
Docker
↓
/srv/docker
```

が本体になります。

## 私なら設計書にはこう書きます

> **ストレージ構成**
>
> * OS領域とアプリケーションデータ領域を分離する。
> * OSはシステムディスクに配置する。
> * Dockerの永続データ（SQL Serverデータ、バックアップ等）はデータディスクへ配置する。
> * 将来的なサーバー移行およびバックアップ容易性を考慮し、データ領域はOS領域と独立して管理する。

### 私からのおすすめ

**「パーティションを分ける」より「別VHDXを追加する」**方が実務的です。

Hyper-VではVHDXの追加・容量拡張・バックアップが容易で、OSディスクとデータディスクを独立して管理できます。あなたの「別Linuxへ移行しやすくしたい」「データを守りたい」という目的にも、この構成が最も適しています。
