---

### なぜ運用設計書なのか

テスト仕様書まで作ると、「システムが完成した」という前提になります。

次に考えるべきなのは、

* 運用担当者は何をするのか
* バックアップはどうするのか
* ログはどこを見るのか
* 障害時はどうするのか
* 定期作業はあるのか

といった**システムを運用するための設計**です。

そのため、

```text
要件
↓
設計
↓
実装
↓
テスト
↓
運用設計
↓
運用手順
```

という流れになります。

### 今回のVM4構成なら

以前一緒に考えたVM4（Windows + SQL Server + ASP.NET + C#クライアント）の学習環境であれば、運用設計書には例えば次のような内容が入ります。

* 運用体制
* サーバー構成
* サービス管理（IIS・SQL Server）
* バックアップ方針
* ログ管理
* ディスク容量監視
* パフォーマンス監視
* アカウント管理
* パッチ適用方針
* 障害対応フロー
* 復旧方針
* 定期メンテナンス

そして運用手順書では、それぞれを具体的な操作に落とし込みます。

* SQL Serverのバックアップ手順
* IIS再起動手順
* Windows Update手順
* ログ採取手順
* 障害発生時の切り分け手順
* サービス起動確認手順
* リストア手順

## 学習目的なら、さらに追加すると良いドキュメント

実務に近づけるなら、ここから以下も作成すると一連の流れを経験できます。

```text
01_事前調査
02_見積書
03_要件定義書
04_基本設計書
05_機能仕様書
06_詳細設計書
07_テスト設計書
08_テスト仕様書
09_運用設計書
10_運用手順書
11_リリース計画書
12_リリース手順書
13_障害対応手順書
14_保守設計書
15_保守手順書
16_プロジェクト完了報告書
```

この構成まで作成すると、設計・開発・テストだけでなく、**運用・保守・リリースまで含めたシステムライフサイクル全体**を一通り学べます。

私としては、次は予定どおり**運用設計書**を作成するのがおすすめです。その後に運用手順書を作れば、「設計 → 実作業」の対応関係も理解しやすくなります。
