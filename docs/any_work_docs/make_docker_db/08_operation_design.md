# 運用設計書（Operation Design）

案件名:
学習用サーバー環境構築および設計書整備

版数:
v1.0

---

# 1. 目的

本書は、構築した学習用サーバー環境を継続的かつ安全に利用するための運用方針を定義する。

具体的な操作方法については、運用手順書で定義する。

---

# 2. 運用対象

本運用設計の対象は以下とする。

* Hyper-V
* VM4
* Ubuntu Desktop LTS
* Docker
* SQL Server
* 関連ドキュメント

---

# 3. 運用体制

本環境は個人学習用途であるため、以下の体制とする。

| 役割  | 担当    |
| --- | ----- |
| 利用者 | 作成者本人 |
| 管理者 | 作成者本人 |
| 運用者 | 作成者本人 |

利用者・管理者・運用者は同一人物とする。

---

# 4. 運用方針

* 本環境は学習用途として利用する。
* 本番運用は対象外とする。
* 構成変更時は関連ドキュメントを更新する。
* 障害発生時は再構築を基本方針とする。
* 運用方法に変更があった場合は、本書を更新する。

---

# 5. サーバー構成

サーバー構成については以下の設計書に従う。

* 基本設計書
* 詳細設計書

本書ではサーバー構成の詳細は定義しない。

---

# 6. サービス管理

## 基本方針

* 必要なサービスのみ導入する。
* 不要となったサービスは停止または削除する。
* 新規サービス追加時は設計書を更新する。

対象例

* Docker
* SQL Server

---

# 7. アカウント管理

## 利用者管理

利用者・管理者・運用者は同一人物とする。

## 認証情報管理

* 初期認証情報は変更する。
* パスワードをドキュメントへ平文で記載しない。
* 認証情報は第三者へ共有しない。

---

# 8. パッチ適用方針

## OS

定期的に更新状況を確認する。

## Docker

必要に応じて更新する。

## SQL Server

必要に応じて更新する。

### 更新時の方針

* 大規模更新前はHyper-Vチェックポイントを取得する。
* 更新後は動作確認を実施する。

---

# 9. バックアップ・復旧方針

## 基本方針

本環境は学習用途であるため、
バックアップ運用ではなく再構築を基本とする。

## バックアップ

* 必要に応じてHyper-Vチェックポイントを取得する。
* ドキュメントは適宜バックアップする。

## 復旧

* 軽微な障害は設定修正により復旧する。
* 復旧が困難な場合は構築手順書に従って再構築する。

---

# 10. 定期メンテナンス

必要に応じて以下を実施する。

* OS更新確認
* Docker更新確認
* SQL Server更新確認
* 不要ファイル整理
* ディスク空き容量確認

---

# 11. セキュリティ運用

* 外部公開は行わない。
* 不要サービスは停止する。
* 不要ポートは開放しない。
* 管理者権限での常時利用は避ける。
* OS・Docker・SQL Serverは必要に応じて更新する。
* 認証情報を適切に管理する。

---

# 12. 変更管理

以下に該当する場合は、関連ドキュメントを見直す。

* OS変更
* Docker構成変更
* SQL Serverバージョン変更
* ネットワーク構成変更
* VM構成変更
* セキュリティ方針変更

更新対象例

* 要件定義書
* 基本設計書
* 詳細設計書
* 構築手順書
* テスト関連資料
* 運用設計書
* 運用手順書

---

# 13. 本フェーズ対象外

本案件は個人学習用途であるため、以下については本フェーズでは対象外とする。

* 定期バックアップ運用
* ログ監視
* ディスク容量監視
* パフォーマンス監視
* 障害対応フロー
* 自動通知
* 冗長化構成
* 高可用性構成
* 24時間365日の運用体制

必要となった場合は、要件定義・設計を見直した上で別途導入を検討する。
