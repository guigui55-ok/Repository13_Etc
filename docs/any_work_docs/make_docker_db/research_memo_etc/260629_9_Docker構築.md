# この順番にした理由

以前話していた

> 将来Ubuntu→Rocky Linuxなどへ移行したい

これを実現するためです。

```
OS
    ↓
Docker Engine
    ↓
Docker Data（別VHDX）
```

という構成にすると、

OSを入れ替えても

```
Docker Engine
```

だけ再インストールすれば、

```
docker compose up
```

だけで復元しやすくなります。

## 私なら構築手順書も少し修正します

最終的には次のような章立てにすると、実務でも見かける流れになります。

```
5. OS初期設定
    5.1 パッケージ更新
    5.2 SSH設定
    5.3 データディスク追加・マウント

6. Docker基盤構築
    6.1 Docker Engine
    6.2 Docker Compose
    6.3 Dockerデータ保存先変更
    6.4 動作確認

7. SQL Server構築
    7.1 Compose作成
    7.2 データ保存先設定
    7.3 起動
    7.4 接続確認
```

この流れにしておくと、**「OS」「Docker基盤」「アプリケーション（SQL Serverなど）」**の責務が分離され、将来ミドルウェアを追加・変更するときも構成を崩さずに管理できます。
