はい。将来的に「OSとデータを分離したい」という目的であれば、**Ubuntu Server内で追加パーティションを作成する**のがおすすめです。

特に以前お話ししたような、

* Dockerのデータ
* PostgreSQL/MySQLなどのDB
* アプリケーションデータ
* バックアップ

を別パーティションに置いておくと、OSの再インストールやVM移行が楽になります。

---

# おすすめ構成

例えば100GBのVHDXなら

| パーティション | サイズ  | 用途               |
| ------- | ---- | ---------------- |
| /       | 30GB | Ubuntu本体         |
| /data   | 70GB | Docker・DB・アプリデータ |

Dockerなら

```
/data/docker
```

DBなら

```
/data/postgresql
```

などに保存します。

---

# 現在の状態を確認

まず現在のディスク構成を確認します。

```bash
lsblk -f
```

または

```bash
sudo fdisk -l
```

おそらく

```
sda
 ├─sda1
 ├─sda2
 └─sda3
```

のようになっていると思います。

---

# 空き容量があるか確認

```
sudo parted /dev/sda print free
```

ここで

```
Free Space
```

が表示されるなら、その領域を使えます。

---

## しかし…

Ubuntu Serverを通常インストールした場合、多くは

```
VHDX全部
　↓
LVM
　↓
/
```

となっています。

つまり

```
パーティションが1個
```

しかなく、

```
空き領域が存在しない
```

ケースが非常に多いです。

その場合は

```
まずLVMを縮小
```

が必要になります。

---

# まず確認したい

以下を実行してください。

```bash
lsblk -f
```

または

```bash
lsblk
```

結果を貼っていただければ、

* LVM構成か
* 普通のext4か
* GPTかMBRか
* このまま分割できるか
* 一度Live ISOが必要か

まで含めて、最も安全な具体的な手順をご案内します。

# もし未使用領域がある場合の手順

例えば未割り当てが70GBあるなら、

## ① parted起動

```bash
sudo parted /dev/sda
```

---

## ② 空きを確認

```
print free
```

---

## ③ 新しいパーティション作成

```
mkpart primary ext4 30GB 100%
```

---

## ④ 終了

```
quit
```

---

## ⑤ ext4作成

```bash
sudo mkfs.ext4 /dev/sda4
```

---

## ⑥ マウントポイント作成

```bash
sudo mkdir /data
```

---

## ⑦ UUID取得

```bash
sudo blkid
```

例

```
UUID="1234-5678"
```

---

## ⑧ `/etc/fstab`編集

```bash
sudo nano /etc/fstab
```

追加

```
UUID=1234-5678 /data ext4 defaults 0 2
```

---

## ⑨ マウント

```bash
sudo mount -a
```

---

## ⑩ 確認

```bash
df -h
```

```
Filesystem
/dev/sda4

Mounted on
/data
```

となれば成功です。

## 学習環境なら、もう1つおすすめの方法があります

まだ環境構築の途中で、Dockerもこれから本格的に使う段階であれば、**VHDXを無理に分割する代わりに、Hyper-Vで2台目の仮想ディスク（例: `Data.vhdx`）を追加する方法**もおすすめです。

この方法なら、

* OSディスク (`Ubuntu.vhdx`)
* データディスク (`Data.vhdx`)

を完全に分離でき、実際のサーバー構成にも近くなります。また、データディスクだけを別VMへ付け替えることもできるため、学習にも役立ちます。

実務でも、OSディスクとデータディスクを分ける構成はよく採用されます。

私としては、**これから構築する段階なら「2つ目のVHDXを追加する方法」の方をおすすめ**します。OSディスクの縮小作業が不要で、安全かつ運用もしやすいためです。
