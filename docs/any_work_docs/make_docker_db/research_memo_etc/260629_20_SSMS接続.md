ちょうどこの画面ですね。

まず確認ですが、**SQL Serverコンテナは起動済み**でしょうか？

```bash
docker ps
```

で

```text
sqlserver    Up ...
```

となっていることが前提です。

---

## SSMS 接続設定

### サーバー名

UbuntuのInternal IPを使用します。

```text
172.16.10.20
```

または

```text
172.16.10.20,1433
```

1433以外を使っていなければ、`172.16.10.20`だけでも構いません。

---

### 認証

プルダウンを

```text
SQL Server 認証
```

へ変更します。

※現在は「Windows認証」になっています。

---

### ユーザー名

```text
sa
```

---

### パスワード

`.env` に設定した

```text
MSSQL_SA_PASSWORD
```

の値を入力します。

---

### データベース

```text
<既定>
```

のままでOKです。

---

### 暗号化

Docker版SQL Serverでは証明書をまだ設定していないため、

```
暗号化
```

を

```text
オプション
```

または

```text
必須
```

のままにして、

**「サーバー証明書を信頼する」**

にチェックを付けてください。

添付画像では

```
□ サーバー証明書を信頼する
```

となっていますので、

✅ チェックを入れます。

## 接続できない場合

次の順番で確認すると原因を切り分けられます。

### ① コンテナ起動確認

```bash
docker ps
```

---

### ② ポート公開確認

```bash
docker ps
```

の PORTS に

```text
0.0.0.0:1433->1433/tcp
```

と表示されているか。

---

### ③ Ubuntu側で1433を待ち受けているか

```bash
sudo ss -tlnp | grep 1433
```

---

### ④ Windows VMから

```cmd
ping 172.16.10.20
```

---

### ⑤ Windows VMから

```cmd
Test-NetConnection 172.16.10.20 -Port 1433
```

PowerShellで実行します。

---

### ここで一つ確認したいこと

**まだ `docker compose up -d` は実行しましたか？**

もし実行済みであれば、以下の2つの結果を貼っていただければ、接続できる状態かどうかをすぐ判断できます。

```bash
docker ps
```

```bash
docker logs sqlserver
```

これで、SQL Server自体の起動状態と、SSMSから接続できる状態かを確認できます。
