Chat:
これはかなり良い視点です。
結論から言うと、

* **プロジェクト固有の恒久情報 → agent（または instructions）**
* **調査・作業ごとの背景や制約 → prompt**
* **特定作業の調査観点 → skill**

に分けるのがおすすめです。

# 作業背景・目的 → prompt は重要（非常に有効）

# 毎回 Prompt に書くのはNG
    管理漏れやユーザー・AIともに負担が増えるため

Agent
→ 長寿命・共通前提

Prompt
→ 今回だけの依頼
    複数回使用するなら、Prompt.mdファイル化しておいてもよい。

推奨：

```text
agents/
└─ enterprise-csharp-agent/
    ├─ AGENT.md
    └─ project_context.md
```



# 調査観点・チェック項目 → skill
    案件が終わったら skill は削除しなくてもよい
    使い終わったらachiveなどに取っておくとよい

skills/
├─ active/
├─ archive/
└─ common/

Copilot機能ごとの、それぞれのとらえ方
Agent
→ 長寿命（半年〜年）

Skill
→ 中寿命（案件〜複数案件）

Prompt
→ 短寿命（作業単位）

# 過去のskillがたまっていくと誤用される可能性はある。
（似たような内容のskillがある場合）
→案件ごとにフォルダを分けておくとよい。

現在の作業コンテキスト（WorkItem）を別管理して、それを Agent が参照する
（Agent.mdに案件とスキル一覧などを書いたりしない）

おすすめ構成。

.github/
├─ AGENT.md
├─ context/
│   ├─ project.md
│   └─ active-work.md
├─ workitems/
│   ├─ WI-001-encrypt-export.md
│   ├─ WI-002-version-check.md
│   └─ archive/
└─ skills/


この場合、promptでagent(context)とWorkItemを指定して、さらに依頼をする運用となる。
依頼方法
```
investigate-agent 使用

active-work を参照

暗号化対象を列挙
```

Agent.md
```
役割:
既存システム調査

現在作業中の内容は
context/active-work.md
参照
```

active-work.md を用意して、ここにメインの作業について記載する。

```
使用可能 Skill:

```




# Agentに記載した、状況や環境情報が毎回読み込まれることについて
一部のソースコードだけ調査したい場合、別ワークスペースに切り出した方がよい？
→ 基本は切り出さない方がよいです。
コード調査は意外と周辺情報が効くため

必要部分だけ修正などするときは、以下のようにする
```依頼例

このメソッドだけ調査してください。
他ファイルは必要になったら参照してください。
修正提案不要。
```

逆に別ワークスペースが向くのは、

・アルゴリズム確認
・構文質問
・LINQ整理
・Regex確認
・単体メソッド改善
