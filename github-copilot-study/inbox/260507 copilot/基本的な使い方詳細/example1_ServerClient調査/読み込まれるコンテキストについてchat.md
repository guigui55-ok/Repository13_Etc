Agentやinstructionsに環境や状況を長々と記載したとして、毎回読み込まれると思いますが、 これはキャッシュ化されて、コンテキストはあまり多くならないと考えてもよいですか？

Chat:
結論からいうと、**「キャッシュされるから気にしなくてよい」とは考えない方がよい**です。
特に GitHub Copilot の `AGENT.md` / `copilot-instructions.md` / Instructions 類は、**論理的には毎回コンテキスト候補として扱われる前提**で設計した方が安全です。

整理するとこうです。

### ① モデル内部で最適化（キャッシュ・圧縮・要約）が行われる可能性はある

実装詳細は公開されていませんが、一般にAI製品側では、

* 同一コンテキストの再利用
* 差分送信
* 要約保持
* 埋め込み検索

のような最適化が入る可能性があります。

ただし、**利用者側から「これはキャッシュ済みだからトークン消費ゼロ」と期待できるものではありません。**

つまり、

❌ 「1万文字 instructions でも一回読んだら以後無料」

ではないです。

---

### ② 実務上は「毎回読まれる前提」で設計した方が失敗しにくい

特に Copilot Agent 系では、

* Agent.md
* copilot-instructions.md
* Skill
* ユーザー入力
* ワークスペース情報
* 開いているファイル
* 関連コード

を合わせてコンテキストが構成されます。

そのため、Instructions を肥大化すると、

* 指示が薄まる
* 関係ないルールが混入する
* 古い案件情報を拾う
* 期待した Skill が選ばれない

という副作用が起きやすくなります。

以前話していた「案件A/Bで Skill 誤使用が心配」という話にも繋がります。

---

### ③ 環境情報は「毎回必要なもの」だけ残す（おすすめ）

例えばこう分割します。

#### AGENT.md（常時必要・短い）

```md
# 共通前提

- リポジトリは複数システム混在
- server/: API
- installer/: インストーラー
- client/: WinForms

変更前に影響範囲確認
```

→ 300〜1000文字くらい目安

---

#### Skill（必要時だけ読む）

```md
skills/
  debug/
  build/
  review/
  release/
```

例：

```md
# build skill

- 手順
- 注意点
- 確認項目
```

---

#### work/

```md
案件A.md
案件B.md
```

都度参照。

---

### ④ 特に避けたいもの

こういうのを Agent に全部入れるのはおすすめしません。

```md
案件履歴全部
過去障害一覧
議事録全文
設計思想全部
用語集全部
```

これらは、

* docs/
* knowledge/
* skill/

に逃がして、必要時だけ参照する方が良いです。

---

なので、質問への回答を一言で言うと、

> **「内部で多少最適化される可能性はあるが、それを前提に長文化しない。Agent / instructions は毎回読む前提で短く保ち、詳細は Skill や別ファイルに逃がす」が実務上おすすめです。**

今後 Skill が大量に増える想定なら、前に話していた「Agent＝ルーター」「Skill＝実処理」という分離はかなり相性が良いと思います。
