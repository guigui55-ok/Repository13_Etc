文字数について、日本語での文字数ですか？（ChatGPTやCopilotは英語に翻訳されると聞いたことがあります） （おそらく、あいまいな日本語にすると、コンテキストやトークンが増えますよね？）

Chat:
良い観点です。結論から言うと、**さきほどの「300～1000文字」は日本語の見た目文字数の目安で、実際に制約になるのは文字数ではなくトークン数です。**

そして、認識として少し補足があります。

* ❌「内部で全部英語翻訳されているので、英語で書いた方が常に有利」
* ⭕「内部ではトークン化される。日本語・英語でトークン効率は多少変わるが、最近のモデルでは昔ほど大差ない」

という理解の方が近いです。

なので、**instructions を英語化する目的が『トークン節約』だけなら、優先度は低め**です。

代わりに効くのは、

1. 書く量を減らす
2. 構造化する
3. 曖昧さを減らす

です。

例えば。

悪い例（日本語・曖昧）：

```md
変更時は必要に応じて関係する部分を確認して、
場合によっては他の関連箇所も見て対応してください。
```

これは意外と重いです。

良い例：

```md
変更対象:
- 原則1コンポーネントのみ
- 跨る場合は確認
```

短いし解釈もぶれません。

---

トークン観点でいうと、一般論としてはこんな傾向があります。

| 書き方       | トークン効率    |
| --------- | --------- |
| 短い箇条書き    | 良い        |
| テーブル      | 良い        |
| 重複説明      | 悪い        |
| 長い自然文     | 悪い        |
| 同義語列挙     | 悪い        |
| JSON/YAML | 普通～良い     |
| 英語短文      | 少し良いことがある |
| 日本語短文     | 十分良い      |

例えば、

長い：

```text
このフォルダはサーバー用です。
サーバー処理が入っています。
APIがあります。
DB接続します。
```

短い：

```text
Server/: API・DB
```

後者の方が効きます。

---

あと、Copilot / Agent 用 instructions だと、日本語特有の問題は「翻訳」よりむしろ**曖昧表現**です。

避けた方がよい例：

```text
基本的には
なるべく
必要に応じて
できれば
通常は
```

推奨：

```text
必須:
禁止:
原則:
対象:
除外:
```

---

あなたのケース（複数プログラム混在）なら、私はむしろ**英語化よりタグ化**をおすすめします。

例：

```md
# Components

[Server]
path: Server/

[Installer]
path: Installer/

[ClientMain]
path: ClientMain/

# Rules

- modify: target_only
- ask_before_cross_component
- verify_shared_code
```

こういう形式は短くて曖昧さも少ないです。

なので、「日本語だとコンテキスト増える？」への答えは、

**少しは増える可能性があるが、英語化より“冗長な文章をやめて構造化する”方が効果が大きい**

になります。
