# 代表的なドキュメント一覧（上流→下流）

## 1. 企画・提案フェーズ

### 企画書

* 「何を作るか」
* ビジネス目的
* 市場・課題
* 効果予測

### 提案書

* 顧客向け
* 構成、費用、スケジュール
* 技術選定理由

### RFP（提案依頼書）

* 顧客側が作ることも多い
* 「こういうシステムが欲しい」

### 見積書

* 工数
* 金額
* ライセンス費

# 2. 要件定義フェーズ

## 要求仕様書

* ユーザーが「やりたいこと」

例：

* CSV出力したい
* 画像表示したい
* 同時接続100人

---

## 要件定義書

* 要求を「システム要件」に落とし込む

例：

* CSV UTF-8対応
* 画像はJPEG/PNG
* PostgreSQL使用

---

---

## ユースケース図

---

## 画面一覧

## 画面遷移図

# 実際の現場でよくある「まとめ方」

特に日本SIでは：

| フェーズ | よく使う  |
| ---- | ----- |
| 上流   | 要件定義書 |
| 設計   | 基本設計書 |
| 実装   | 詳細設計書 |
| テスト  | 試験仕様書 |
| 運用   | 運用手順書 |

が中心になります。

# 特に中小開発で重要な考え方

全部を重厚に作る必要はありません。

実務では：

* 「将来変更されそうな部分」
* 「他人が触る部分」
* 「障害時に困る部分」

を重点的にドキュメント化します。

逆に：

* 単純な内部処理
* すぐ捨てるツール
* 個人用スクリプト

は軽量化することも多いです。

---

# 個人的には超重要だと思うドキュメント
