GitHub Copilot の **Hook** は、**Copilot がある処理を実行する前後に、自動で任意のコマンドやスクリプトを実行する仕組み**です。

MCP・Agent・Skillとは役割が異なるため、まず違いを整理すると分かりやすいです。

| 機能       | 主な役割            | 実行タイミング        |
| -------- | --------------- | -------------- |
| Agent    | AIの振る舞い・判断を定義   | プロンプト実行時       |
| Skill    | 特定作業の手順を教える     | Agentが必要と判断した時 |
| Prompt   | 一度だけの指示         | ユーザー実行時        |
| MCP      | 外部ツール・APIをAIに公開 | AIがツール利用時      |
| **Hook** | コマンドを自動実行       | 指定イベント発生時      |

つまり Hook は **AIではなく、VS Code側で動く自動化機能**です。

---

例えば

```

        ↓
Hook
        ↓
npm test
        ↓
失敗
        ↓
Copilotがテスト結果を見て修正
```

このような流れを作れます。

## あなたの場合の使い分け

今までの相談内容からすると、次のような使い分けがよさそうです。

* **Agent**：回答方針（Ask、Ask_Light、Ask_Deepなど）
* **Skill**：ドキュメント整理、レビュー、設計手順
* **Hook**：Git操作、整形、テスト、Markdown整理、自動リネーム
* **MCP**：社内ツール、独自データベース、ファイル検索、特殊ツールの利用

この役割分担にすると、それぞれの責務が明確になります。

なお、Hookは比較的新しい機能で、現在利用している **VS Code** と **GitHub Copilot Chat** のバージョンによって利用できるイベントや設定方法が異なる場合があります。もし興味があれば、**実際の設定ファイル（JSON）や、Hookを使って「Markdown整理」や「Gitコミット前チェック」を自動化する具体例**も紹介できます。

現在の **VS Code の GitHub Copilot Hooks (Preview)** では、利用できるイベントは **8種類**あります。([Visual Studio Code][1])

| イベント               | 発火タイミング                  | 主な用途               |
| ------------------ | ------------------------ | ------------------ |
| `SessionStart`     | 新しいチャットセッションの最初のプロンプト送信時 | 初期化、プロジェクト情報収集     |
| `UserPromptSubmit` | ユーザーがプロンプトを送信したとき        | プロンプト監査、コンテキスト追加   |
| `PreToolUse`       | Copilot がツールを呼び出す直前      | 危険な操作のブロック、承認、入力変更 |
| `PostToolUse`      | ツール実行直後                  | フォーマット、ログ出力、テスト実行  |
| `PreCompact`       | 会話履歴を圧縮（コンテキスト削減）する直前    | 必要な情報の保存           |
| `SubagentStart`    | サブエージェント起動時              | ログ、初期化             |
| `SubagentStop`     | サブエージェント終了時              | 結果の集約、後処理          |
| `Stop`             | エージェントの処理が終了したとき         | レポート作成、通知、クリーンアップ  |

([Visual Studio Code][2])

この設定は

## あなたの開発スタイルだと

これまでの相談内容を見ると、Hookは**「AIに何かを考えさせるための仕組み」というより、「AIの前後で定型処理を自動化する仕組み」**として使うのが最も効果的だと思います。

といった構成にすると、あなたがこれまで検討してきた **Agent・Skill・Prompt** の仕組みを補完する形で、開発フロー全体をかなり自動化できます。

```

        ↓

        ↓
```
