## Ask と Plan の違い

Ask は、通常の相談・調査・説明に向いています。たとえば、

「この処理はどこで使われていますか？」
「このエラーの原因は何ですか？」
「この設計で問題ありますか？」
「この仕様を整理してください」

のように、**答えを返してもらう**用途に向いています。

一方で Plan は、添付ファイルを見る限り、単なる調査エージェントではなく、**実装前の計画作成専用エージェント**です。定義上も「唯一の責任は計画であり、絶対に実装を開始しない」と明記されています。さらに、コードベース調査 → ユーザー確認 → 調査結果と決定事項を計画にまとめる、という流れが指定されています。

つまり Plan は、
**「すぐ直して」ではなく、「直す前に、どう直すべきかを調査して計画化して」**
という場面に向いています。

## Plan が強いところ

Plan は、特に以下のような作業で効果を発揮しそうです。

1つ目は、**複数ファイル・複数機能にまたがる修正**です。Plan には Discovery / Alignment / Design / Refinement の流れがあり、既存機能・類似実装・ブロッカー・曖昧点を調べてから計画に落とし込む構成になっています。

たとえば、

「この機能変更の影響範囲を調べて、実装計画を作って」
「既存版と別Edition版を同時起動可能にする修正計画を作って」
「この画面追加に必要な修正ファイル・テスト観点を整理して」

のような依頼です。

2つ目は、**実装前に手戻りを減らしたい作業**です。Plan は、ユーザーに確認すべき曖昧点を `vscode/askQuestions` で確認し、大きな仮定を置かないように設計されています。
なので、仕様が少し曖昧な作業、既存仕様への影響が怖い作業に向いています。

3つ目は、**あとで実装エージェントに渡す前提の作業**です。Plan には `Start Implementation` という handoff が定義されており、計画が固まったら別の agent に実装を渡す前提になっています。

## 逆に、Plan を使わなくてもよい場面

以下は Ask で十分だと思います。

「このコードの意味を教えて」
「この関数の使い方を教えて」
「このエラーの原因を推測して」
「このファイルを翻訳して」
「この仕様書の表現を直して」
「このコマンドを教えて」

こういうものは、**計画書を作るほどではない**ので Ask の方が軽いです。

## 実務的な使い分け

おすすめはこうです。

**Ask を使う場面**
調査、説明、設計相談、原因調査、軽い修正方針の確認。

**Plan を使う場面**
実装前に、影響範囲・修正手順・対象ファイル・検証方法・除外範囲まで整理したいとき。

**Agent / 実装系を使う場面**
計画が固まった後、実際にファイルを修正してほしいとき。

あなたの用途に寄せると、普段の「調査」だけなら Ask でよいです。
ただし、調査の目的が **「このあと実装するための作業計画を作ること」** なら Plan を使う価値があります。

たとえば、依頼文はこういう感じが良さそうです。

この変更を実装する前に、Plan エージェントで計画を作成してください。

目的:
〇〇を実現したいです。

やってほしいこと:

* 関連する既存実装を調査する
* 影響範囲を整理する
* 修正対象ファイルを洗い出す
* 実装手順を段階化する
* 検証方法を提示する
* 不明点や判断が必要な点を整理する

この時点では、まだファイル修正はしないでください。

かなり相性が良いのは、あなたが最近相談していたような **「既存アプリに別Edition対応を入れる」「複数ファイルを日付順にリネームする」「Copilot用Agent/Skill構成を設計する」** みたいな作業です。
こういう場合は Ask で調査するより、Plan で最初に計画化した方が、後続の実装が安定しやすいと思います。
