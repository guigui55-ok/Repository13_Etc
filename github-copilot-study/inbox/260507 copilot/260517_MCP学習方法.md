# なぜ先にCopilot Chatなのか

MCPは「AIを強化するための道具」です。

なので先に、

```text
AIに何を頼むと便利か
AIは何が苦手か
どこで人間確認が必要か
```

を体感しておく必要があります。

これを知らずにMCP化すると、

```text
とりあえず全部MCP
↓
構成が複雑化
↓
便利なのか微妙
↓
保守コスト増加
```

になりがちです。

---

# Copilot Chatだけでもかなり学べる

まずはMCPなしで、

```text
・仕様書貼り付け
・関連コード貼り付け
・影響範囲相談
・設計相談
・テスト観点相談
・リファクタ相談
```

を繰り返すだけで、

```text
「AIに向く作業」
「AIに向かない作業」
```

がかなり見えてきます。

---

# その後、「面倒な部分」をMCP化する

Copilot Chatを使っていると、だんだんこう思い始めます。

```text
毎回この仕様書探すの面倒だな…
毎回 grep するの面倒だな…
関連ファイル列挙を自動化したいな…
```

ここがMCP化ポイントです。

つまりMCPは、

```text
AIのための検索補助・情報収集補助
```

として使うのが本質に近いです。

---

# あなたの案件だと特に有効そうな流れ

かなり実務に近い形でいうと、

## Step1：Copilot Chatで調査

```text
「この機能変更で影響ありそうな箇所は？」
```

↓

AIが、

```text
・画面
・Service
・DAO
・SQL
・設定ファイル
```

などを挙げる

---

## Step2：人間が不足を感じる

```text
でも実際に関連仕様書探すのが面倒
grep結果整理が面倒
```

---

## Step3：MCP化

```text
search_specs()
search_source()
find_related_classes()
```

を追加

---

## Step4：AIの調査能力が強化される

```text
「受注登録変更の関連仕様書と関連クラス一覧を出して」
```

が実現できる

# この順番のメリット

この順番だと、

```text
MCPを「必要になったものだけ」作れる
```

のが大きいです。

つまり、

```text
実務上価値があるMCP
```

だけ残ります。

# 最初にやると良いこと

## Copilot Chatに慣れる

特に以下です。

```text

```

これが超重要です。
