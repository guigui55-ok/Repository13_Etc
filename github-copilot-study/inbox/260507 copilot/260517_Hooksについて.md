[GitHub Copilot 公式サイト](https://github.com/features/copilot?utm_source=chatgpt.com) の「Hooks」は、文脈によって少し意味が変わるのですが、最近の [Visual Studio Code](https://code.visualstudio.com?utm_source=chatgpt.com) + [GitHub Copilot](https://github.com/features/copilot?utm_source=chatgpt.com) の流れで出てくる「Hooks」は、主に

* 「Copilot の動作タイミングに処理を差し込む仕組み」
* 「AIエージェント実行前後に自動処理を入れる仕組み」

を指します。

特に、最近の Copilot Agent / MCP / workflow 系の文脈では、

* Agent が作業開始する前
* コマンド実行前
* ファイル変更後
* タスク完了後

などのタイミングで、独自処理を自動実行できる「フック機構」として扱われています。

---

# イメージ

例えば、

```text
Copilot Agent がコード修正開始
    ↓
[Pre Hook]
    - git status確認
    - バックアップ
    - lint実行

    ↓
Copilot がコード編集

    ↓
[Post Hook]
    - テスト実行
    - フォーマット
    - ログ保存
```

のような感じです。

---

# Hooks が useful な理由

Copilot はかなり自動化が進んでいるため、

* 「AIに好き勝手変更されるのが怖い」
* 「実行前に安全確認したい」
* 「変更後に自動テストしたい」

という需要があります。

Hooks を使うと、

* AI作業の前後に安全処理
* 品質チェック
* 自動ログ
* 自動Git操作

などを入れられます。

これは、Toshiさんが興味を持っている

* 自動ビルド
* PowerShell連携
* テスト自動化
* タスクランナー
* 複数ツール連携

とかなり相性が良いです。

# Hooks の具体例

## ① 保存時 Hook

ファイル保存時に:

```powershell
dotnet build
```

を自動実行。

---

## ② Copilot編集後 Hook

Copilot がコード変更後に:

```powershell
dotnet test
```

を実行。

---

## ③ Agent 実行前 Hook

Agent が作業する前に:

```powershell
git branch backup/auto
```

を実行。

# Hooks と MCP の違い

ここ、かなり混同しやすいです。

| 機能    | 役割               |
| ----- | ---------------- |
| MCP   | AIに「外部ツールを使わせる」  |
| Hooks | 特定タイミングで「自動処理する」 |

つまり:

* MCP = AIの手を増やす
* Hooks = AI作業の前後ルール

です。

# 注意点

Hooks は便利ですが、

* 無限ループ
* 自動実行暴走
* 危険コマンド実行
* 重い処理

に注意が必要です。

特に:

```powershell
git clean -fdx
```

みたいなのを Hook に入れると危険です。

# -----------
現時点では、主に **3通り**あります。

## 1. VS Code の Agent Hooks

VS Codeでは Preview 機能として、リポジトリ内に以下を作ります。

```text
.github/hooks/format.json
```

例：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "type": "command",
        "command": "dotnet build"
      }
    ]
  }
}
```

これで、Copilot Agent がツール実行後に `dotnet build` を実行できます。VS Code公式では、`.github/hooks/*.json` をワークスペース Hook として読み込むと説明されています。([Visual Studio Code][1])

---

## 2. GitHub Copilot Cloud Agent 用

GitHub上の Copilot coding agent / cloud agent で使う場合も、リポジトリに置きます。

```text
.github/hooks/任意名.json
```

ただし、**デフォルトブランチに存在している必要があります**。([GitHub Docs][2])

テンプレート例：

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [],
    "postToolUse": [],
    "sessionStart": [],
    "sessionEnd": [],
    "userPromptSubmitted": [],
    "errorOccurred": []
  }
}
```

---

## 3. Copilot CLI 用

Copilot CLI でも Hooks を使えます。

リポジトリ単位：

```text
.github/hooks/任意名.json
```

ユーザー単位：

```text
%USERPROFILE%\.copilot\hooks\
```

Windowsの場合、GitHub公式の例では **PowerShell 7.0以上** が必要とされています。([GitHub Docs][3])

---

## まず試すなら

Toshiさんの場合、まずは VS Code の作業リポジトリでこれが良いです。

```text
.github/hooks/post-build.json
```

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "type": "command",
        "command": "dotnet build"
      }
    ]
  }
}
```

用途としては、

```text
Copilot Agent が修正
↓
Hookで dotnet build
↓
ビルドエラーがあれば確認
```

という流れです。

注意点として、Hooks はまだ Preview で、設定形式や動作が変わる可能性があります。([Visual Studio Code][1])
