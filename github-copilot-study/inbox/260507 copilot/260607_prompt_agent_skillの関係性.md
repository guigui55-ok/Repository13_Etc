はい、かなり近い認識です。
ただ、厳密には **prompt は agent＋skill を束ねるものというより、「今回の依頼内容そのもの」** と考えると整理しやすいです。

以前の話を踏まえると、私はこう理解しています。

| 要素         | 役割               | 粒度 | 再利用性 |
| ---------- | ---------------- | -: | ---: |
| **agent**  | どう振る舞うか（役割・思考方針） |  大 |    高 |
| **skill**  | どう作業するか（手順・ノウハウ） |  中 |    高 |
| **prompt** | 今回何をしてほしいか（実行指示） |  小 |  低〜中 |

イメージすると…

```text
Prompt
 ├─ Agent（役割）
 │     └─ Skill（作業手順）
 │            └─ ソース・仕様書・ファイル
```

なので、あなたの表現を少し直すなら、

> prompt = agent と skill を組み合わせて呼び出すための、一時的な作業依頼

です。

たとえば、今回の「仕様調査」なら。

### agent（役割）

```text
code-investigation-agent
```

役割：

* 推測禁止
* 根拠を示す
* 仕様書とコードを突合
* 影響範囲を出す

↓

### skill（手順）

```text
csharp-file-write-investigation
```

手順：

* File.Write 系検索
* 呼び出し元列挙
* 一覧化

↓

### prompt（今回だけ）

```text
プロジェクト内でファイル出力処理に暗号化を追加したい。

code-investigation-agent を使用。
csharp-file-write-investigation skill を使用。

対象:
- src/
- spec/

成果物:
- write_points.md

出力:
- 書き込み箇所一覧
- 呼び出し元
- 暗号化対象候補
- 修正難易度
```

ここで重要なのは、

* **agent は使い回す**
* **skill は蓄積する**
* **prompt は捨ててもよい**

ということです。

実は、あなたが前に話していた「作業履歴を md 化して再利用したい」という運用だと、

```text
チャット履歴
↓
良い依頼を抽出
↓
prompt化
↓
繰り返し使うなら skill化
↓
さらに複数skillを束ねたくなったら agent化
```

という流れがかなり相性が良いです。

なので、「prompt は一時依頼、使い回したくなったら skill、複数 skill を統括したくなったら agent」という昇格ルールを作っておくと管理しやすくなると思います。
