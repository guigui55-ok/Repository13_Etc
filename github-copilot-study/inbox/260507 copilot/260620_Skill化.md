## さらに効果的な方法案

**提案1：「問題・手順・発見」の3層分離**
```md
## 作業手順
実施した手順を以下の形式で簡潔に記載してください：
- ステップ1: 〇〇を実施 → 結果/判断
- ステップ2: ××を確認 → 結果/判断

## Skill候補（同じパターンが3回以上出現したら）
目的：
前提条件：
入力：
処理ステップ：
出力：
```

**理由**：
- ステップの「結果/判断」をセットで記録すると、後でSkill化時に「条件分岐」が明確になる
- 「3回以上」という具体的な基準を入れると、AIの出力が安定する

---

**提案2：別アプローチ「事後分析スタイル」**

毎回Instructionsに載せるのではなく、定期的に（例：週1回）過去の作業ログを眺めて、パターンを「手動で」Skill候補として記録する方法もあります：

- 当日の会話ログをMarkdownで残す
- 週末に「今週使ったパターン3つ」を自分で抽出
- **その時点でSkill候補として構造化**

これだと：
- ✅ AIの過剰出力を避けられる
- ✅ 人間の視点で「本当に再利用価値ある？」を判断できる
- ✅ 記憶も深くなる（セレクション効果）

## もっと良い書き方

### 1. 条件を明確にする

例:

```md
以下の条件を満たす場合にのみ、回答の末尾に追加してください。

- 回答本体だけでは作業の流れが伝わりにくいと判断した場合
- 再利用できそうな手順が含まれている場合
- 今回の作業が過去の作業と同じパターンになりそうな場合
```

### 2. `必ず` ではなくてもよいが、基準は提示する

例:

```md
回答の末尾に、以下を簡潔に記載してください。

## 作業手順
- ステップ1: 〇〇を実施 → 結果/判断
- ステップ2: ××を確認 → 結果/判断

## Skill候補
- 同じ作業パターンがある場合、または再利用価値が高い場合のみ記載
```

## 具体的に使うなら

`必要に応じて` を使いたい場合は、次のように補足すると良いです。

```md
必要に応じて、以下のいずれかに該当する場合だけ回答末尾に付けてください。

- 手順を明示することで、判断の根拠がわかりやすくなる
- 今回の流れが別のタスクでもそのまま使えそうである
- 他の人が同じ作業を再現するために手順が必要である
```

---

## まとめ

- `必要に応じて` はやや曖昧なので、できれば「どんな場合に必要か」を補う
- 具体的な条件を示すと、AIの出力が安定する
- 目的は「観察しやすく、Skill化候補が見つかること」なので、基準を入れると良いです
